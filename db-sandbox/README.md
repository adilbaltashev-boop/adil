# Песочница «Кредитный модуль банка» — PostgreSQL + DBeaver

Учебная база данных под курс системного аналитика (проект «Кредитный модуль банка», 8 занятий:
ноябрь 2026 — август 2027). Внутри: готовая схема, ~5000 вымышленных клиентов с корректными ИИН,
8000 заявок, 6000 кредитов с аннуитетными графиками и 76 000 платежей, включая просрочки, и задания
с решениями к каждому занятию.

Все данные сгенерированы: люди, ИИН, телефоны и номера договоров вымышленные.

## Установка на Mac

Нужны две вещи: **сервер PostgreSQL** (где живёт база) и **DBeaver** (окно, через которое ты с ней работаешь).

### Шаг 1. PostgreSQL — выбери один вариант

**Вариант А. Postgres.app (локально, бесплатно).**
1. Скачай с postgresapp.com и перетащи в «Программы».
   Если macOS попросит пароль администратора, а его нет, переходи к варианту Б.
2. Открой Postgres.app → **Initialize**. Сервер запустится на `localhost:5432`.
3. Параметры подключения: host `localhost`, port `5432`, база `postgres`, пользователь — имя твоей
   учётной записи Mac, пароль пустой.

**Вариант Б. Бесплатный облачный PostgreSQL (без установки).**
Зарегистрируйся в сервисе с бесплатным PostgreSQL (например, Neon или Supabase), создай проект и
возьми из панели host, базу, пользователя и пароль. В DBeaver при подключении на вкладке SSL включи
`sslmode = require`. Песочница занимает около 60 МБ, бесплатных лимитов хватает.

### Шаг 2. DBeaver

1. Скачай **DBeaver Community** с dbeaver.io (версия для Apple Silicon или Intel — смотри
   «Об этом Mac»). Без прав администратора приложение можно запускать прямо из «Загрузок».
2. **New Database Connection** (вилка с плюсом) → **PostgreSQL** → введи параметры из шага 1 →
   **Test Connection**. При первом подключении DBeaver предложит скачать драйвер — соглашайся.

### Шаг 3. Загрузить песочницу

1. В DBeaver: **File → Open File** → `sql/01_schema.sql`.
2. Проверь, что вверху редактора выбрано твоё подключение (Active datasource).
3. **Execute SQL Script** — ⌥ X (кнопка с листком и зелёной стрелкой). Именно скрипт, а не ⌘ Enter.
4. Так же выполни `sql/02_seed.sql` (около 5–30 секунд), затем `sql/03_checks.sql`.
   В результате должна быть строка `OK | 4999 | 8000 | 6062 | 75787`.
5. Нажми F5 на подключении: появится схема `credit`. Правый клик по ней → **View Diagram** покажет ER-диаграмму.

Числа в пункте 4 получены на PostgreSQL 16. На другой версии они могут немного отличаться, а
`OK` должен быть всегда.

Песочницу можно перезалить в любой момент: `01_schema.sql` удаляет схему `credit` и создаёт её заново.

### Если есть терминал и psql

```bash
PGHOST=localhost PGDATABASE=postgres ./verify.sh
```

Скрипт заливает всё, прогоняет решения и миграции и проверяет, что в конце песочница вернулась
в исходное состояние. Пароль, если нужен, передавай через переменную `PGPASSWORD`, не записывай в файлы.

## Схема в двух словах

```
regions ─< branches ─< employees
   │           │            │ (эксперт)
   └─< clients ─< loan_applications >─ loan_products
                     │ ├─< application_status_history
                     │ └─< credit_bureau_checks (jsonb)
                     └─ loans ─< repayment_schedule ─ payments
                          └─< collaterals
```

Полная диаграмма с атрибутами — в [уроке 01](lessons/01_er_model.md).
«Сегодня» в песочнице — `sandbox_today()` = 25.11.2026: относительно этой даты считаются
просрочки, чтобы данные не «устаревали».

Что намеренно оставлено несовершенным, чтобы было что улучшать на уроках:
у `payments` нет индекса по `loan_id`, у `clients` нет индекса по фамилии (урок 04).
