# Урок 06. Использование ИИ для проектирования БД и SQL

Занятие курса: 31 мая 2027. Курс показывает ChatGPT; всё ниже так же работает с Claude и другими моделями.

## Где ИИ реально экономит время системному аналитику

| Задача | Что даёт ИИ | Что проверяешь сам |
|---|---|---|
| Черновик модели данных по описанию бизнеса | список сущностей, атрибутов, связей | бизнес-правила, которых не было в описании; лишние «умные» таблицы |
| DDL для PostgreSQL | `CREATE TABLE` с типами и ограничениями | типы денег и дат, `NOT NULL`, уникальность, `ON DELETE` |
| ER-диаграмма | код Mermaid / PlantUML / DBML по DDL | кардинальности (1:1 vs 1:N) |
| SQL-запрос по вопросу на русском | готовый запрос | **запустить** и сверить число строк; JOIN-ловушки (урок 08) |
| Объяснение чужого запроса или плана | разбор по строкам | — |
| Маппинг и тестовые данные | таблица маппинга, INSERT-ы | формат дат и денег, придуманные колонки |

## Шаблоны промптов

**1. Модель данных по описанию**

```
Ты — системный аналитик в банке. По описанию бизнеса ниже предложи логическую модель данных.
Формат ответа: таблица «Сущность | Атрибуты | Ключ | Связи (с кардинальностью)».
Отдельным списком: допущения, которые ты сделал, и вопросы к бизнесу, без ответа на которые модель неоднозначна.
Не добавляй сущности, которых нет в описании; если считаешь, что нужна — вынеси в «предложения».
Описание: <вставь текст из урока 01>
```

**2. Физическая модель для PostgreSQL**

```
По логической модели ниже напиши DDL для PostgreSQL 16 в схеме credit.
Требования: суррогатные ключи identity; деньги numeric(14,2); даты date, моменты времени timestamptz;
статусы — text с CHECK на список значений; NOT NULL везде, где поле обязательно по смыслу;
индексы на все внешние ключи; COMMENT ON TABLE/COLUMN на русском.
После DDL перечисли ограничения целостности, которые нельзя выразить в DDL и надо проверять в коде.
Модель: <…>
```

**3. ER-диаграмма**

```
Построй ER-диаграмму в синтаксисе Mermaid erDiagram по этому DDL. Покажи PK, FK, UK и кардинальности
связей. Подписи связей — по-русски. DDL: <вставь sql/01_schema.sql>
```

**4. SQL по вопросу**

```
Схема PostgreSQL (DDL ниже). Напиши запрос: <вопрос по-русски>.
Требования: явные JOIN с ON, без SELECT *, даты фильтровать диапазоном.
Кратко объясни, как запрос работает, и предупреди, если в нём возможно размножение строк при JOIN.
DDL: <только нужные таблицы>
```

## Чек-лист проверки ответа ИИ

1. Запрос **выполнился** в DBeaver без ошибок (модели выдумывают колонки и функции из других СУБД).
2. Число строк совпадает с ожиданием; посчитай отдельно `count(*)` главной таблицы.
3. Нет размножения строк при JOIN (суммы не раздуты, урок 08, задание 6).
4. Даты: границы включительно/исключительно, часовой пояс.
5. NULL: `count(колонка)` vs `count(*)`, `NOT IN` с NULL в подзапросе возвращает пусто.
6. В DDL: деньги не во `float`, у статусов есть `CHECK`, у внешних ключей есть индексы.
7. Нет персональных данных в промпте: **не вставляй в публичные чат-боты реальные ИИН, ФИО и номера
   договоров** из рабочих систем. Для промптов используй песочницу или обезличенные данные.
