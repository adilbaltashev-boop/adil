# Урок 08. JOIN через DBeaver

Занятие курса: 2 августа 2027. Решения: [`solutions/08_joins.sql`](../solutions/08_joins.sql).

## Виды JOIN

| JOIN | Что возвращает | Типичная задача в кредитном модуле |
|---|---|---|
| `INNER JOIN` | только пары, нашедшие друг друга | заявка + клиент + продукт |
| `LEFT JOIN` | все строки слева, справа — что нашлось, иначе NULL | все эксперты и их заявки, включая экспертов без заявок |
| `LEFT JOIN … WHERE правая.id IS NULL` | строки слева без пары (anti-join) | клиенты без заявок, неоплаченные строки графика |
| `RIGHT JOIN` | зеркало LEFT; на практике переписывают в LEFT | — |
| `FULL JOIN` | все строки с обеих сторон | сверка двух выгрузок или двух периодов |
| `CROSS JOIN` | все комбинации | матрица «регион × продукт» |
| self-join | таблица соединяется сама с собой | время между статусами заявки |
| `LATERAL` | подзапрос, видящий текущую строку слева | последний платёж по каждому кредиту |

## Три ловушки, на которых ошибаются даже опытные

1. **Условие на правую таблицу в `WHERE` убивает `LEFT JOIN`.** Строки без пары имеют NULL,
   и `WHERE a.channel = 'mobile_app'` их выкидывает. Условие нужно переносить в `ON`.
   В песочнице: неправильный запрос возвращает 2152 клиента, правильный — все 4999 (задание 5).
2. **Размножение строк.** Если присоединить к кредиту и платежи, каждая строка кредита
   повторится столько раз, сколько у него платежей, и `sum(principal)` вырастет в разы.
   Сначала агрегируй «многую» сторону в подзапросе, потом соединяй (задание 6).
3. **`count(*)` после `LEFT JOIN`** считает строку с NULL как 1. Для «сколько нашлось справа»
   используй `count(правая.id)` (задание 4).

Правило самопроверки: перед `GROUP BY` посчитай строки «сырого» JOIN и сравни с числом
строк главной таблицы. Если строк стало больше, чем ожидалось, ищи размножение.

## Задания

1. Выведи последние 20 заявок с ФИО клиента и названием продукта.
2. Для просроченных кредитов выведи номер договора, код продукта, регион клиента и сумму (пять таблиц).
3. Найди клиентов, не подавших ни одной заявки. Сделай двумя способами: `LEFT JOIN … IS NULL` и `NOT EXISTS`.
4. Выведи всех кредитных экспертов с числом их заявок, включая тех, у кого заявок нет.
5. Для каждого клиента посчитай заявки через мобильное приложение (у кого их нет — 0). Сначала напиши
   с условием в `WHERE`, посмотри, сколько строк потерялось, потом исправь.
6. По каждому клиенту выведи сумму выдач и сумму платежей. Сравни наивный двойной JOIN и правильный вариант.
7. Найди неоплаченные строки графика со сроком в прошлом и посчитай дни просрочки.
8. Через self-join таблицы `application_status_history` посчитай, сколько часов заняло решение по заявке.
9. Сравни число заявок по продуктам за 2025 и 2026 годы в одной таблице (`FULL JOIN`).
10. Построй матрицу «регион × продукт» с числом заявок, включая нули.
11. Выведи последний платёж по каждому кредиту.
12. Посчитай остаток основного долга по живым кредитам в разрезе регионов.

## Самоконтроль с ИИ

Попроси модель объяснить готовый запрос построчно и предсказать, сколько строк он вернёт, а
затем запусти его и сравни. Если модель уверенно назвала неправильное число, это хороший
повод разобраться, где именно она (или ты) ошиблась в понимании JOIN.
