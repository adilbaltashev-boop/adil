# Урок 02. Разработка требований к миграциям БД

Занятие курса: 18 января 2027. Файлы: [`migrations/`](../migrations/).

## Что такое миграция

Миграция — версионированное изменение схемы и/или данных: файл `V003__что_меняем.sql`
плюс откат `U003__…`. Инструменты (Flyway, Liquibase, Alembic) запоминают, какие версии
уже применены, и накатывают недостающие по порядку. Два вида:

- **миграция схемы** — добавить колонку, таблицу, индекс, ограничение;
- **миграция данных** — перенести/пересчитать значения (backfill), перенести данные между системами.

Примеры из кредитного модуля: добавить ставку пени, перевести «цель кредита» из текста в справочник,
перенести портфель из старой АБС в новую.

## Обратная совместимость: главное правило

Во время выката старая и новая версии приложения **работают одновременно** (несколько
серверов обновляются по очереди, мобильные клиенты не обновляются месяцами). Значит, каждая
миграция должна работать и со старым, и с новым кодом.

**Паттерн «расширить → перенести → сузить» (expand / migrate / contract):**

1. **Expand** — добавляем новое, ничего не удаляя: новая колонка без `NOT NULL`, новая таблица.
2. **Migrate** — переносим данные пачками; пока живы обе версии, синхронизируем поля (триггер или код).
3. **Contract** — когда старой версии нигде не осталось: `NOT NULL`, удаляем старое.

| Изменение | Опасный способ | Безопасный способ |
|---|---|---|
| Переименовать колонку | `RENAME COLUMN` — старый код падает сразу | новая колонка + синхронизация → переключить код → удалить старую |
| Сделать колонку обязательной | `ADD COLUMN … NOT NULL` без DEFAULT | nullable → backfill → `SET NOT NULL` |
| Сменить тип | `ALTER COLUMN TYPE` — перезапись всей таблицы с блокировкой | новая колонка нужного типа + перенос |
| Удалить колонку | сразу `DROP` | сначала код перестаёт читать, потом `DROP` в отдельном релизе |
| Добавить ограничение | `ADD CONSTRAINT CHECK` — проверка всей таблицы под блокировкой | `NOT VALID`, потом `VALIDATE CONSTRAINT` |

**Распространённые ошибки:** удалили колонку, которую читает отчёт или интеграция; добавили
`NOT NULL` без значения по умолчанию; поменяли формат значения (`'issued'` → `'ISSUED'`), не
предупредив потребителей; не продумали откат: после `DROP COLUMN` данные не вернуть.

## Влияние НФТ на миграции

| НФТ | Последствие для миграции |
|---|---|
| «Сервис доступен 24/7» | никаких долгих блокировок: `CREATE INDEX CONCURRENTLY`, `NOT VALID`, backfill пачками, `SET lock_timeout = '3s'` |
| Объём (десятки млн строк) | `UPDATE` всей таблицы одним запросом — часы и раздутая таблица; переносить пачками по 5–10 тыс. |
| RPO/RTO, откат | на каждую миграцию — откат; перед необратимыми шагами — бэкап или выгрузка |
| Аудит, регулятор | миграции данных логируются: сколько строк, кто запускал, сверка «до/после» |

## Миграция данных между разными СУБД

Пример: перенос кредитного портфеля из старой АБС на Oracle в новую систему на PostgreSQL.

| Oracle | PostgreSQL | Подвох |
|---|---|---|
| `NUMBER(14,2)` | `numeric(14,2)` | `NUMBER` без точности → `numeric`, не `float`: деньги во `float` теряют копейки |
| `VARCHAR2(100)` | `varchar(100)` / `text` | в Oracle длина может быть в байтах, кириллица в UTF-8 занимает 2 байта |
| `DATE` | `timestamp` | Oracle `DATE` хранит **время**; перенос в `date` молча обрежет часы |
| `''` (пустая строка) | `''` | в Oracle пустая строка = `NULL`; после переноса `WHERE x IS NULL` находит меньше строк |
| `CLOB` | `text` | — |
| `SEQUENCE.NEXTVAL` | `identity` / sequence | после переноса сдвинуть sequence на `max(id) + 1`, иначе дубли ключей |
| часовые пояса | `timestamptz` | договориться, в каком поясе хранились даты (Asia/Almaty, UTC+5) |

Сверка после переноса: количество строк по каждой таблице, контрольные суммы по деньгам
(сумма выдач, остатков, платежей по месяцам), выборочная сверка 100 договоров «глазами»,
проверка ссылочной целостности (нет платежей без кредита).
