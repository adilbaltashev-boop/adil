# Урок 07. Маппинг данных: БД и JSON

Занятие курса: 28 июня 2027. Решения: [`solutions/07_json.sql`](../solutions/07_json.sql).

## Зачем аналитику маппинг

Между экраном, API и базой данные проходят три формы: поле на экране → поле в JSON → колонка
в таблице. Маппинг — это таблица, которая для каждого поля говорит, откуда оно берётся, в
каком формате передаётся и как преобразуется. Без него разработчики фронта, бэка и
интеграций додумывают это сами, и потом выясняется, что сумма пришла строкой, дата в другом
формате, а статус в другом регистре.

## JSON за 5 минут

- Объект `{ "ключ": значение }`, массив `[ ... ]`, значения: строка, число, `true/false`, `null`, объект, массив.
- В JSON нет типа «дата» и «деньги»: даты передают строкой ISO 8601 (`"2026-11-25"`,
  `"2026-11-25T10:00:00+05:00"`), деньги — числом или строкой. Это решение надо **записать в маппинге**.
- Принятые соглашения API: ключи в camelCase (`contractNumber`), в БД — snake_case (`contract_number`).

## JSON в PostgreSQL

| Оператор | Что делает | Пример |
|---|---|---|
| `->` | взять поле как JSON | `response -> 'active_loans'` |
| `->>` | взять поле как текст | `response ->> 'score'` |
| `::int`, `::numeric` | привести текст к типу | `(response ->> 'score')::int` |
| `jsonb_array_elements` | развернуть массив в строки | `CROSS JOIN LATERAL jsonb_array_elements(...)` |
| `@>` | «содержит» | `response -> 'active_loans' @> '[{"type":"mortgage"}]'` |
| `json_build_object`, `json_agg` | собрать JSON из строк | ответ API |

В песочнице ответы кредитных бюро лежат в `credit_bureau_checks.response` (jsonb):

```json
{
  "score": 640,
  "overdue_days_max": 0,
  "requests_last_30d": 2,
  "active_loans": [
    { "lender": "Банк А", "type": "card", "balance": 350000, "monthly_payment": 25000, "overdue_days": 0 }
  ]
}
```

## Шаблон маппинга

Пример для экрана «Мои кредиты» в мобильном приложении и метода `GET /api/v1/clients/{clientId}/loans`.

| № | Поле на экране | JSON-путь в ответе | Тип JSON | Источник в БД | Правило / преобразование | Обяз. |
|---|---|---|---|---|---|---|
| 1 | ФИО | `fullName` | string | `clients.last_name, first_name, middle_name` | через пробел, отчество может отсутствовать | да |
| 2 | ИИН | `iinMasked` | string | `clients.iin` | первые 6 цифр + `******`, полный ИИН в ответ не отдаём | да |
| 3 | Номер договора | `loans[].contractNumber` | string | `loans.contract_number` | как есть | да |
| 4 | Продукт | `loans[].product.name` | string | `loan_products.name` через `loans → loan_applications → loan_products` | — | да |
| 5 | Сумма кредита | `loans[].principal` | number | `loans.principal` | 2 знака после запятой, валюта отдельным полем | да |
| 6 | Валюта | `loans[].currency` | string | `loan_products.currency` | ISO 4217, `KZT` | да |
| 7 | Ставка | `loans[].annualRate` | number | `loans.annual_rate` | номинальная, % годовых | да |
| 8 | Дата выдачи | `loans[].issuedOn` | string | `loans.issued_on` | `YYYY-MM-DD` | да |
| 9 | Статус | `loans[].status` | string (enum) | `loans.status` | верхний регистр: `ACTIVE, OVERDUE, CLOSED, WRITTEN_OFF` | да |
| 10 | Ближайший платёж | `loans[].nextPayment.dueDate`, `.amount` | object / null | первая строка `repayment_schedule` без записи в `payments` | `null`, если кредит погашен | нет |

Колонки, которые стоит держать всегда: **обязательность**, **формат** (даты, деньги, enum),
**правило преобразования** и **что делать, если значения нет** (`null`, поле отсутствует или пустая строка — это
три разных ответа, и это надо решить явно).

## Задания

1. Выведи `score`, `overdue_days_max` и число активных кредитов из ответов ПКБ.
2. Найди заявки, где бюро показало просрочку больше 30 дней.
3. Разверни массив `active_loans` в строки: кредитор, тип, остаток, ежемесячный платёж.
4. Посчитай коэффициент долговой нагрузки: (платежи по чужим кредитам + наш платёж) / доход.
5. Найди заявки, у клиентов которых есть ипотека в другом банке (оператор `@>`).
6. Собери JSON-ответ метода `GET /api/v1/clients/{clientId}/loans` по маппингу выше.
7. Разбери входящий JSON заявки из приложения и проверь, что каждое поле ложится в колонку
   `loan_applications` (найден ли клиент по ИИН, существует ли продукт, сумма в пределах продукта).
8. Составь маппинг для экрана «График платежей»: номер, дата, сумма, из них проценты, статус
   (оплачен / ожидается / просрочен). Подсказка: статус вычисляется из `repayment_schedule`,
   `payments` и `sandbox_today()`.

## Автоматизация с ИИ

Хорошо работает связка: DDL таблиц + пример JSON → «составь таблицу маппинга с колонками
… и пометь поля, для которых нет источника в БД». Модель быстро даёт черновик, но
типичные ошибки нужно проверять вручную: путает обязательность, придумывает колонки,
которых нет в DDL, и молча выбирает формат дат. Шаблон промпта — в [уроке 06](06_ai_for_db.md).
